# BUG-01 — Невозможно создать задачу

### Краткое описание

Основной сценарий создания задачи не реализован. При запуске текущего `src/app.py` приложение только выводит сообщение об успешном запуске и не предоставляет операции создания задачи.

### Окружение

- Python 3.x
- ОС: Windows
- Репозиторий: `ptpm-lab1-bolgova`
- Ветка: `main`
- Файл: `src/app.py`

### Предусловия

- Проект склонирован локально.
- Пользователь находится в каталоге проекта.
- Запускается текущая версия `src/app.py`.

### Шаги воспроизведения

1. Запустить `src/app.py`.
2. Попробовать выполнить сценарий создания задачи:
   - указать название `Smoke`;
   - указать описание `Release`;
   - подтвердить создание.
3. Проверить, появилась ли созданная задача и можно ли получить её по ID.

### Фактический результат

Программа выводит:

```text
Проект запущен успешно!
```

После этого функциональность создания задачи отсутствует: невозможно передать название и описание, создать объект задачи, получить ID и добавить задачу в список.

### Ожидаемый результат

Система должна принять название и описание, создать задачу с непустым уникальным ID и статусом `new`, после чего задача должна быть доступна в списке.

### Приоритет

**Critical**

Создание задачи является основным сценарием системы. Без него невозможно использовать большую часть последующих операций.

### Связь с артефактами

- Требования: `FR-01`, `FR-02`, `FR-03`
- Сценарий: `SC-01`
- Тест-кейс: `TC-01`
- Чек-лист: `CL-01`

### Доказательство

Фрагмент текущего `src/app.py`:

```python
def main():
    print("Проект запущен успешно!")

if __name__ == "__main__":
    main()
```

Дополнительное доказательство для Issue: скриншот терминала после запуска программы.

# BUG-02 — Отсутствует получение списка задач

### Краткое описание

Система не предоставляет операцию просмотра списка существующих задач, хотя требование и тест-кейс предусматривают получение всех сохранённых задач.

### Окружение

- Python 3.x
- ОС: Windows
- Репозиторий: `ptpm-lab1-bolgova`
- Ветка: `main`
- Файл: `src/app.py`

### Предусловия

- В проекте должна существовать хотя бы одна созданная задача.
- Программа запущена.

### Шаги воспроизведения

1. Запустить `src/app.py`.
2. Попытаться запросить список задач.
3. Проверить наличие в результате ID, названия, описания и статуса существующих задач.

### Фактический результат

Операция получения списка задач отсутствует. После запуска отображается только:

```text
Проект запущен успешно!
```

Список задач пользователю не возвращается.

### Ожидаемый результат

Система должна возвращать все существующие задачи с полями `id`, `title`, `description` и `status`.

### Приоритет

**High**

Без просмотра списка пользователь не может проверить созданные задачи и их актуальное состояние.

### Связь с артефактами

- Требование: `FR-05`
- Сценарий: `SC-02`
- Тест-кейс: `TC-03`
- Чек-лист: `CL-02`

### Доказательство

Фрагмент `src/app.py` содержит только функцию запуска и вывод сообщения о запуске. Операция получения списка задач отсутствует.

Дополнительное доказательство для Issue: скриншот терминала после запуска.

# BUG-03 — Невозможно изменить статус задачи

### Краткое описание

Операция изменения статуса существующей задачи отсутствует. Пользователь не может перевести задачу, например, из `new` в `in_progress`.

### Окружение

- Python 3.x
- ОС: Windows
- Репозиторий: `ptpm-lab1-bolgova`
- Ветка: `main`
- Файл: `src/app.py`

### Предусловия

- В системе должна существовать задача со статусом `new`.
- Программа запущена.

### Шаги воспроизведения

1. Запустить `src/app.py`.
2. Выбрать существующую задачу.
3. Передать ей статус `in_progress`.
4. Получить задачу повторно.
5. Проверить статус и ID.

### Фактический результат

Операция изменения статуса не реализована. Программа не принимает ID задачи и новый статус.

### Ожидаемый результат

Система должна установить статус `in_progress`, сохранить остальные поля и оставить ID задачи неизменным.

### Приоритет

**High**

Изменение статуса является основной операцией жизненного цикла задачи.

### Связь с артефактами

- Требования: `FR-08`, `FR-17`
- Сценарий: `SC-03`
- Тест-кейс: `TC-04`
- Чек-лист: `CL-03`

### Доказательство

Текущий `src/app.py` не содержит функций работы с задачами или статусами и после запуска только выводит сообщение:

```text
Проект запущен успешно!
```

Дополнительное доказательство для Issue: скриншот терминала после запуска.

# BUG-04 — Отсутствует поиск задач по ключевому слову

### Краткое описание

Функция поиска по названию и описанию задачи отсутствует. Также отсутствует предусмотренная требованиями проверка без учёта регистра.

### Окружение

- Python 3.x
- ОС: Windows
- Репозиторий: `ptpm-lab1-bolgova`
- Ветка: `main`
- Файл: `src/app.py`

### Предусловия

В хранилище должны находиться задачи, например:

- название: `PyTest Case`;
- описание: `Проверка поиска по ключевому слову`.

### Шаги воспроизведения

1. Запустить `src/app.py`.
2. Выполнить поиск по слову `pytest`.
3. Выполнить поиск по слову `PYTEST`.
4. Сравнить результаты.
5. Повторить проверку для ключевого слова из описания.

### Фактический результат

Функция поиска отсутствует. Программа после запуска только выводит:

```text
Проект запущен успешно!
```

Результаты поиска не возвращаются.

### Ожидаемый результат

Система должна искать ключевое слово в названии и описании задачи независимо от регистра. Поиск `pytest` и `PYTEST` должен возвращать одинаковый набор результатов.

### Приоритет

**High**

Поиск является отдельной функциональной возможностью, указанной в требованиях и покрытой обязательным тестом.

### Связь с артефактами

- Требования: `FR-10`, `FR-11`
- Сценарий: `SC-04`
- Тест-кейс: `TC-06`
- Чек-лист: `CL-05`, `CL-06`, `CL-07`

### Доказательство

В текущем `src/app.py` отсутствует реализация поиска и работы с задачами.

Дополнительное доказательство для Issue: скриншот терминала после запуска.

# BUG-05 — Данные задач не сохраняются и не загружаются из JSON

### Краткое описание

Требуемое JSON-хранилище не реализовано. Приложение не сохраняет актуальное состояние задач и не загружает ранее сохранённые данные при запуске.

### Окружение

- Python 3.x
- ОС: Windows
- Репозиторий: `ptpm-lab1-bolgova`
- Ветка: `main`
- Файл: `src/app.py`

### Предусловия

- Проект запущен.
- Пользователь располагает путём к JSON-файлу хранения.

### Шаги воспроизведения

1. Запустить `src/app.py`.
2. Создать задачу `Smoke` с описанием `Release`.
3. Выполнить сохранение.
4. Завершить программу.
5. Запустить программу повторно.
6. Проверить, восстановилась ли задача из JSON.

### Фактический результат

Функциональность создания, сохранения и загрузки задач отсутствует. `src/app.py` не открывает JSON-файл, не записывает задачи и не восстанавливает состояние.

### Ожидаемый результат

После успешного сохранения JSON должен содержать актуальный объект `tasks` с задачами. После повторного запуска задачи должны восстановиться с теми же ID, названиями, описаниями и статусами.

### Приоритет

**Critical**

Потеря состояния между запусками делает невозможным выполнение основного сценария работы с сохранёнными задачами.

### Связь с артефактами

- Требования: `FR-13`, `FR-14`, `FR-18`
- Сценарий: `SC-05`
- Тест-кейс: `TC-08`
- Чек-лист: `CL-09`, `CL-10`

### Доказательство

В текущем `src/app.py` отсутствует импорт/работа с JSON и файловым хранилищем; программа содержит только функцию `main()` с выводом сообщения о запуске.

Дополнительное доказательство для Issue: скриншоты состояния каталога до и после запуска, показывающие отсутствие создаваемого JSON-хранилища.

# 4. Дополнительное задание

## Выбранный дефект: BUG-05 — отсутствие сохранения и загрузки JSON

### Почему этот дефект нельзя считать мелочью

Сохранение и восстановление состояния являются частью основного назначения «Сервиса задач». Если данные не сохраняются, результаты работы пользователя теряются после завершения программы. Это влияет на основной пользовательский сценарий и связано с требованиями `FR-13`, `FR-14` и `FR-18`.

### Что может пойти не так, если исправить дефект без ретеста

Разработчик может добавить сохранение только для создания задачи, но забыть сохранять изменения статуса, названия или описания. Также может возникнуть ситуация, когда файл записывается, но после повторного запуска данные читаются с потерей одного из обязательных полей. Поэтому после исправления необходимо проверить полный цикл: создать → изменить → сохранить → перезапустить → загрузить → сравнить данные.

### Какой один тест добавить для защиты от регрессии

**Регрессионный тест:** создать задачу с известными `id`, `title`, `description` и `status`, изменить описание и статус, сохранить JSON, перезапустить модуль и проверить, что все четыре поля восстановлены без изменений ID.

Связь: `FR-18`, `SC-05`, `TC-08`, `CL-09`, `CL-10`.
